## 1. 각 역할 오프닝

### 1-1. Planner (기획자) [Confirmed]

**MVP 핵심 흐름**:
판매 등록 → 마진 계산(예상) → 정산 import(실마진) → 사업비 차감 → 순이익 → 파트너 배분 → 세무사 리포트

**우선순위 정렬**:
1. 사업비용 입력 + 카테고리 + 증빙 상태 (세무 핵심)
2. 월별 정산 자동 집계 (판매장부 → 사업비용 → 순이익)
3. 파트너 N명 정산
4. 세무사 제출용 Excel 리포트
5. 마진계산기 (예상값 자동 적용 + 수동 override)
6. 정책 관리 화면 (마켓 수수료, 세금, 풀필먼트, 반품, 광고)
7. 대시보드 (월 매출/순이익/마진율 추세)

**추가 제안**:
- 카테고리별 기본 목표 마진율 설정
- 정산 마감/세무 신고일 알림
- 정산 확정 워크플로우 (DRAFT → CONFIRMED → 잠금)
- 온보딩 마법사 (SaaS화를 위한 사전 작업, MVP 이후)

### 1-2. Designer [Confirmed]

**관리자 업무툴 UX 원칙 재확인**: 데이터 밀도 우선, 키보드 입력 흐름, 상태 배지로 즉시 인지.

**정책 자동값 UX**:
- 자동 입력된 필드는 회색 배경 + 좌측 작은 i 아이콘
- i 클릭 시 "어떤 정책에서 왔는지, 마지막 확인일, 신뢰도 상태"
- 사용자가 수정하면 노란 배경 + "수동 수정됨" 배지
- 수정 시 사유 입력 모달 (선택, 옵션)

**예상 vs 실제 비교 UX**:
- 마진계산 화면에 토글: [예상 | 실제]
- 두 값을 나란히 표시할 수 있는 비교 뷰
- 차이가 ±5% 초과 시 빨간 배지
- 대시보드: "예상 대비 실제 격차 큰 상품 TOP 10"

**추가 제안**:
- 모바일 반응형: **조회 화면만** (창고/외근). 대량 입력은 데스크톱 전용
- 색약·다크 테마는 Post-MVP
- 표 셀의 인라인 편집 (Enter=저장, Esc=취소, Tab=다음 셀)
- 일괄 선택 + 일괄 수정 (대량 데이터 운영툴 필수)

### 1-3. User / 세무 담당자 [Confirmed]

**세무사 제출 자료의 핵심**: "숫자보다 **증빙·짝맞춤·확정 여부**가 더 중요." 세무사가 신뢰할 수 있어야 함.

**필수 추가 항목**:
- **증빙 상태 워크플로우**: 증빙없음 → 확인필요 → 증빙있음 → 세무사전달완료. 단계별 화면에 카운트 표시
- **매입-매출 짝맞춤(대사)**: 쿠팡 정산금 vs 판매장부 합계 차이 표시
- **정산 확정 잠금**: 한번 확정한 월별 정산은 변경 불가. 정정은 별도 "정정 정산"으로 다음달에 처리
- **분기별 부가세 신고 일정** (1/4월/7/10월 25일): 알림 + 분기별 부가세 참고 리포트 자동 생성

**세무사 협업**:
- 세무사 계정 초대 (읽기 + 코멘트 권한)
- 세무사가 "이 비용 증빙 다시 보내주세요" 코멘트 가능
- 세무사가 "전달 완료" 상태 변경 가능

**적자월 정책 — A안 추천**:
- 적자월은 분배 0, 손실은 `loss_carryover_balance`에 누적
- 다음 흑자월에서 우선 차감 후 남은 금액으로 분배
- 이유: 세무상·정서상 자연스럽고, 동업자 간 분쟁 소지 낮음

**고위험 항목**:
- 카드 결제자(개인 카드) vs 사업 카드 구분 → `paid_by_user_id` + `is_personal_card`
- 사적 비용 vs 사업 비용 구분 → `is_business_use` 컬럼
- 둘 다 비용 등록 시 명시 → 세무사가 필터링 가능

## 3. 고도화 제안 (백로그)

Planner/Designer/User가 토의 중 나온, MVP에는 안 들어가지만 기록은 남기는 항목:

- **AI 자동 분류**: 비용 영수증 OCR + 카테고리 자동 추천
- **세무사 대시보드**: 여러 셀러 통합 관리 화면 (SaaS 모드)
- **공급처 가격 알림**: 도매꾹/1688 가격 변동 → 마진 영향 즉시 알림
- **반품 패턴 분석**: 카테고리/상품별 반품률 추적, 반품 위험비 자동 보정
- **광고 ROAS 자동 학습**: 쿠팡 광고 데이터 import → 카테고리별 권장 ROAS
- **자금 흐름 시뮬레이션**: 정산일/카드 결제일/사업비 결제일 기반 월 현금흐름 예측
- **부가세 매입세액 자동 매칭**: 매입세액 공제 가능 여부 자동 판단(세무사 검토 전제)
- **자동 정산 워크플로우**: 매월 N일 자동 정산 산출 → 관리자 검토 → 자동 분배 송금 트리거(은행 API)
- **마켓별 정책 자동 비교**: "이 상품 쿠팡 vs 11번가 vs 네이버 어디서 가장 마진 좋은가"
- **재무제표 자동 생성**: 손익계산서/재무상태표 초안 (세무사 검토 전제)

## 5. Handoff (Planner+Designer+User → PM/Architect)

### Summary
세무 리포트·정책 관리·대시보드·정산 확정 잠금·세무사 협업이 MVP에 들어와 범위가 확장됨. 적자월은 carryover로 확정. 사업 형태 결정이 필요.

### Decisions
- MVP에 새로 들어오는 16개 항목 확정 (위 표)
- 적자 정책: carryover
- 사적/사업 비용 구분 컬럼 추가

### Open Questions
- 사업 형태 (공동/단독)
- 알림 채널
- 세무사 합류 여부

### Risks
- MVP 범위 팽창 → 일정 리스크. PM이 Must/Should 우선순위 재정렬 필요
- 정책 테이블 12종 = DB 복잡도 증가 → DBA 부담

### Required Inputs for Next Role
- PM: MVP 우선순위 재정렬 (Must vs Should 다시 보기)
- DBA: 정책 테이블 패밀리 + audit_log + 정산 확정 잠금 스키마
- BE: 예상/실마진 분리, 정책 snapshot 패턴

### Handoff Target
PM / Architect (그리고 동시에 DBA+BE 기술 세션으로 병렬)
