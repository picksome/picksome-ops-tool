6 데이터 정합성 규칙

6-1. 정책 시간 범위

  • 동일 (org_id, 정책키, effective 기간) 중복 금지 → exclusion constraint or 트리거
  • 새 버전 등록 시 이전 row의 effective_to = new.effective_from - 1
  • 정책 row hard delete 금지 (reliability_status = 'DEPRECATED' 로 대체)

6-2. 정산 잠금

  • status = LOCKED 인 monthly_settlement의 자식 (partner_settlement, loss_carryover_ledger) 변경 금지 → 트리거 또는 BE 가드
  • expenses.linked_settlement_id 가 LOCKED 정산을 가리키면 그 expense도 수정 금지

6-3. 분배 합계

  • partner_settlement의 RATIO 분배 합 + PRIORITY 합 = monthly_settlement.distributable_amount (BE 검증)
  • partner_share_policy의 share_ratio 합 = 1.0000 (effective 기간 + applies_year_month 단위)

6-4. 금액 단위

  • 모든 금액 컬럼 NOT NULL DEFAULT 0
  • supply + vat = total 일관성 (generated column 또는 트리거)
  • quantity, sale_price > 0 CHECK

6-5. 보안

  • password_vault_entry.memo 평문 비밀번호 패턴 거부 (CHECK)
  • app_user.password_hash 평문 패턴 거부 (CHECK)
  • seed/sample 데이터에 실제 계정 사용 금지 (운영 정책)

6-6. Soft delete

  • UNIQUE 제약은 partial: WHERE deleted_at IS NULL
  • 외래키 참조는 logical (BE가 deleted_at 확인)
