## 4. 사용자 관점 추가 요청 (PM 검토 필요)

세무 검증 중 식별된 보완 사항:

1. **"이 비용은 세무공제만 OFF, 정산공제는 ON"** 같은 분리 케이스가 빈번. → `is_tax_deductible`, `is_settlement_deductible` 컬럼 OK. UI 에서 두 개를 잘못 매핑하지 않게 명확한 라벨 (이미 디자인 반영)
2. 부가세 신고 시 매입세액 공제 가능한 영수증의 분류가 까다로움 → MVP 는 `is_tax_deductible` 만으로 단순화, **공제 가능 여부의 세무 판단은 세무사가 책임** (Disclaimer 라벨 명시)
3. 카드 환불 / 매입 환출은 음수 비용으로 입력 가능해야 함 → `total_amount` 음수 허용 필요 (현 ERD: CHECK 미정). **수정 권고** → DBA 회신 필요
4. 분기 부가세 신고 후 LOCKED 정산을 추가 정정하는 경우 → REOPENED 워크플로우로 처리. 세무사가 사유와 함께 요청.
5. 운영자가 동일 카테고리·동일 결제수단·동일 결제자 비용을 **연속 5건씩** 입력하는 경우가 잦음 → "직전 값 복사" 단축키(Ctrl+D) 추가 권장
