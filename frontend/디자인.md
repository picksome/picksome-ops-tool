# PICKSOME OPS TOOL - UI/UX Design Spec

## 1. Design Direction

PICKSOME OPS TOOL의 디자인 방향은 “셀러용 Finance Command Center”다.

이 툴은 일반적인 예쁜 대시보드가 아니라, 상품 소싱, 마진 계산, 판매 장부, 사업비용, 월별 정산, 수익배분, 세무사 제출용 리포트를 빠르게 처리하는 내부 운영 콘솔이다.

디자인 목표:

* 엑셀보다 빠르게 입력할 수 있어야 한다.
* 숫자와 마진율이 한눈에 보여야 한다.
* 적자, 마진 하락, 증빙 누락, 정산 오류가 즉시 드러나야 한다.
* 사용자는 “지금 무엇을 봐야 하는지” 바로 알 수 있어야 한다.
* 트렌디한 SaaS 관리자툴 느낌은 유지하되, 장부/정산 업무에 맞게 실용성을 우선한다.

키워드:

* Modern SaaS Admin
* Finance Dashboard
* Seller Operations Console
* Clean Data Table
* Quiet Luxury UI
* High Information Density
* Accountant-ready Report UI

## 2. Overall Mood

전체 분위기는 “밝고 정돈된 회계/운영 콘솔”로 잡는다.

기본 모드는 Light Mode다.
Dark Mode는 지원 가능하게 만들되, MVP에서는 Light Mode 완성도를 우선한다.

느낌:

* 배경은 밝은 회색 계열
* 카드와 테이블은 흰색
* 테두리는 얇고 은은하게
* 그림자는 거의 쓰지 않거나 매우 약하게
* 색상은 상태값과 경고에만 제한적으로 사용
* 숫자는 굵고 선명하게
* UI는 조용하지만, 위험 정보는 강하게 보이게

피해야 할 디자인:

* 쇼핑몰 랜딩페이지 느낌
* 과한 그라데이션
* 과한 애니메이션
* 네온 컬러
* 너무 어두운 다크 대시보드
* 카드만 많은 예쁜 통계 페이지
* 실제 업무 입력이 불편한 디자인

## 8. Dashboard Design

Dashboard는 “오늘 무엇을 봐야 하는지” 알려주는 화면이다.

### Top KPI Cards

상단에는 6개 KPI 카드를 배치한다.

1. 이번 달 총매출
2. 이번 달 실마진
3. 평균 마진율
4. 사업비용
5. 분배 가능 순이익
6. 증빙 누락 건수

각 카드 구성:

* Label
* 아이콘(톤별 컬러 chip 배경 — brand/success/info/warning/neutral) + 카드 상단 2~3px accent bar로 카드 간 리듬 구분
* Main value (32px, 기존 28px보다 확대)
* 전월 대비 변화 — 색칠된 pill 배지(plain text 아님)
* 작은 설명 문구

예시:
이번 달 실마진
₩2,483,500
[+12.4% vs 지난달] (녹색 pill)
사업비용 차감 전 기준

**2026-07-27**: 6개 카드 각각 톤 배정 — 총매출(info) / 실마진(success) / 평균마진율(info, 목표미달 시 warning) /
사업비용(neutral) / 분배가능순이익(brand, 대시보드 핵심 숫자) / 정산상태(neutral).
KPI 카드 하단에 월별 매출·실마진 추세 Area Chart(Recharts) 추가 — 브랜드 컬러(#4F46E5)/성공 컬러(#059669)
그라데이션 area fill로 표현(배경 그라데이션이 아닌 차트 자체 시각화이므로 §2 "과한 그라데이션 금지" 규칙과 상충하지 않음).

### Dashboard Sections

1. 월별 매출/마진 추세 차트
2. 판매처별 매출 비중
3. 상위 수익 상품 TOP 5
4. 적자/저마진 상품
5. 증빙 누락 비용
6. 최근 정산 상태
7. 자동화 배치 상태

### Dashboard UX Rule

Dashboard는 모든 데이터를 다 보여주는 화면이 아니다.
위험하거나 중요한 항목을 먼저 보여준다.

우선 노출:

* 적자 상품
* 마진율 20% 미만 상품
* 증빙 누락
* 정산 미확정
* 배치 실패
* 수수료 정책 검토 필요

## 20. Claude Implementation Instruction

When implementing the UI, follow these rules:

* Use shadcn/ui components as the base.
* Use Tailwind utility classes.
* Use a consistent design token system.
* Do not create random custom styles for each page.
* Use reusable components for MoneyText, ProfitText, MarginRateBadge, StatusBadge, KpiCard, DataTable, and PageHeader.
* Do not implement business calculation logic in the frontend.
* Display BE calculation results.
* All Korean labels must be clear and business-friendly.
* Make tables practical before making them beautiful.
* Prioritize readability, sorting, filtering, and export actions.
* Ensure every important destructive action has confirmation.
* Ensure every CLOSED settlement is visually locked.
* Ensure tax report pages clearly state that reports are accountant-review materials, not final tax filings.

Final UI goal:
The user should feel that this is not an Excel replacement, but a professional seller operations command center.
